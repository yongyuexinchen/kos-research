## 1. 判定（TL;DR）

**假设判定：支持（证据强度：强，S 级证据为主）——但必须加限定语。**

- "AI+大数据/NL2SQL/智能BI/Data Agent 是 2026 年 AI 应用开发主流方向之一"：**成立**。开源生态活跃（多个 1.7万-2.8万 star 项目 2026 年仍在高频更新）、学术前沿热（SIGMOD'26 有 Data Agents 教程）、全行业厂商 2025H2-2026 密集产品化（Snowflake/Databricks/微软/AWS/Oracle/IBM/Tableau/腾讯云/阿里瓴羊）。
- "值得作为主项目方向"：**成立但需差异化**。简单 NL2SQL demo 已严重内卷（"90% 准确率 100% 无用"是 2026 年行业主流叙事），主项目必须做成"企业级数据 Agent"（语义层 + 评测 + 多轮 + 可信校验），正好与用户 1 年数仓治理经验形成护城河。
- 方向阶段判断：**当前主流 + 上升期**（真实企业场景远未解决：Spider 2.0 上最强模型仅解 6%），2027 年就业竞争力：**中高，但纯"NL2SQL 工程师"岗少，需求在"数据 Agent / 智能BI 产品"岗**。

## 4. ③ 'AI Agent + 数据'结合趋势（Data Agent / RAG over structured data / 图谱+RAG）

- **学术定调（S 级，来自开源库与引用）**：HKUSTDial/awesome-data-agents（2026-08-05 仍在更新）配套两篇综述：《A Survey of Data Agents: Emerging Paradigm or Overstated Hype?》（arXiv:2510.23587，2025-10，**SIGMOD 2026 有 3 小时官方教程**）和清华李国良团队《Data Agents: Levels, State of the Art, and Open Problems》（arXiv:2602.04261，2026-02）。**数据库顶级会议（SIGMOD）为 Data Agents 开设教程 = 学术界正式承认其为前沿范式**。
- **范式迁移（S 级，来自 Spider 2.0 官方方法）**：基准官方解法从"生成一条 SQL"变成 **Spider-Agent（tool-call 智能体，在真实 Snowflake/DBT 环境里执行 workflow）**——评测标准本身 Agent 化。
- **RAG over structured data 成熟化**：Text-to-SQL 本身即"结构化数据 RAG"；2026 年主流做法=语义层/指标层（WrenAI 的 MDL、dbt Semantic Layer 生态）替代早期"schema 灌进 prompt"的裸 RAG——**'语义层/上下文层'成为数据 Agent 的标准组件**（a16z "Your Data Agents Need Context"、Neo4j 语义层案例同向印证）。
- **图谱+RAG**：Neo4j 官方（2026-05）与 Tableau 图技术驱动的 headless analytics（2026-05）均出现"图谱 × Agent × 分析"叙事；GraphRAG 技术路线在企业数据治理（血缘图/指标依赖图）场景有天然契合（L3 补充）。
- **MCP 标准化**：Oracle NL2SQL Agent 走 MCP；MCP Server 让 AI Agent 访问 SQL 数据库成标配叙事（Cloud Wars，2026-04-15）——**数据访问正成为 Agent 工具生态的标准件，'数据 Agent'不是孤岛方向，而是 Agent 通用能力的垂直化**。
- 判读：**'AI Agent + 数据'不是概念炒作，而是 2025-2026 数据基础设施的既定方向**；数据 Agent = Agent 技术栈（工具调用/MCP/多轮）+ 数据工程（语义层/治理/血缘/评测）的交叉点——交叉点人才稀缺，恰好是用户背景的切入点。

## 6. 对'应用开发者主项目应该往哪靠'的建议

**结论：往'企业级数据 Agent（语义层 × Agent × 治理）'靠，不要往'裸 NL2SQL demo'靠。**

1. **项目定位**：做一个"对话式企业数据分析 Agent"（对标 WrenAI GenBI / 腾讯云 DataBuddy 的迷你版），而非"Text-to-SQL 生成器"。卖点=**可信、可治理、可评测**。
2. **必须包含的差异化组件**（按 2026 行业标准）：
   - **语义层/指标层**：自己定义 MDL（指标口径/维度/关系），替代"裸 schema 进 prompt"——这是 2026 年公认的分水岭（WrenAI/a16z/Neo4j 同向）。
   - **多轮对话状态管理**：追问澄清（"上月"指哪个月）、上下文继承——Spider 2.0 和"90% 无用"叙事的核心痛点。
   - **结果可信校验**：生成 SQL 的语义校验（防 fan-out 双计数、加总不一致——sqlsure 这类 2026 新工具在做的事）、执行后对账。
   - **自建评测集**：用 Spider 2.0/BIRD 方法论建 50-100 条企业场景评测，项目里展示"准确率从 X 到 Y 的迭代过程"——这是把"无用准确率"变成"可信工程证据"的关键。
   - **数据治理背景的显性化**：血缘、质量规则、指标口径管理作为 Agent 的"上下文来源"——**直接复用你 1 年 WeData/Hive/达梦经验，这是别人抄不走的**。
3. **技术栈建议**：Python + LLM API（DeepSeek/Claude 级）+ LangGraph 或纯 MCP 工具调用 + PostgreSQL（你已会）或达梦（差异化国产库）+ 可选 DuckDB 演示成本控制；UI 用现成前端（Streamlit/开源 BI 壳）即可，精力放后端工程。
4. **时间分配**（2026.09-2027.01 主项目）：60% 语义层+评测+可信校验，20% 多轮/Agent 编排，20% 展示（README/演示视频/技术博客三连）。
5. **求职翻译**：简历/面试用词用"数据分析 Agent / 智能问数 / Agentic BI"，岗位对标"Agent 开发（数据向）、智能BI 研发、数据平台 AI 化"；作品集里放"90% 无用"叙事的反例证明（你的评测与对账能力）。
