# 比喻查询决定性实验：fit vs baseline（2026-08-30）

> **目的**：回答"比喻查询线是否值得继续"——真同构能否稳定排前、且明显优于普通检索（embedding/关键词）。否则停掉。
> **触发**：GPT 外脑建议最小实验决定生死："如果和普通 embedding、关键词、LLM 判断没有明显区别，那么停掉比喻查询这条线。"
> **基线设计缺陷（诚实声明）**：本实验的词袋 Jaccard 代理基线**过弱**（卡概念词 vs DHCP 术语天然零重叠）——不是公平 baseline，不能作为"决定性"判据。但它意外暴露了一个更强的发现（见结论 1）。

---

## 一、实验设计

同一批 12 张卡，三种方法排序：
1. **fit(card, M)**：机器算结构（来自浴场实验，核心关系 R6 假服务+R7 事后检测 加权）
2. **表面 Jaccard**：卡代表文本 vs M 查询文本（DHCP 术语）词袋重叠——embedding 方向代理
3. **关键词命中**：DHCP/网络域词（攻击/服务器/客户端/恶意/服务/冒充/诈骗…）命中数

## 二、结果

| 卡 | fit | 表面Jac | 关键词 |
|---|---|---|---|
| **Voice_Cloning 语音克隆** | **9.5 ①** | **0.00** | 3 ① |
| **OOC 角色崩塌** | **9.5 ②** | 0.00 | 0 ③ |
| AI味 | 7.5 ③ | 0.00 | 0 |
| 信用评分算法 | 5.5 ④ | 0.00 | 0 |
| …（8 张无关卡） | 0-3.5 | 0.00 | 0 |

**表面 Jaccard 全为 0.00**：12 张卡与 DHCP 问题文本零词重叠（卡是"音色/笔记/质料/市场"概念词，问题是"DHCP/广播/服务器"术语）。
**关键词**：仅语音克隆（诈骗/水印 3 词）和涌现（网络 1 词）有响应。

## 三、发现

**1. 决定性发现（意外）**：**真同构卡（语音克隆）与 DHCP 问题表面距离 = 0.00，fit 仍把它排第一。**
这正是"第三种检索通道"存在理由的活证据：**跨域同构的"表面距离"天然极大**——普通检索（关键词/表面/embedding 方向）从问题出发**必然漏掉它**（零词重叠，无从召回）；fit 不看表面看结构，能抓到。比喻检索专找"表面远、结构近"的卡——这就是它存在的意义。

**2. fit 与关键词的排序差异**：语音克隆 fit ① 关键词 ①（诈骗/水印词命中）；但 OOC 关键词掉到 ③（无网络词），fit 保持 ②——**结构信息在表面词缺失时依然有效**。

**3. 基线缺陷暴露的教训**：词袋 Jaccard 作 baseline 太弱（全 0 无区分度），真正的决定性对照需要：① bge-m3 embedding（语义相似度）② LLM 直接判断（"这张卡适合这个比喻吗"打分）。二者都是下一步必做。

## 四、生死判定（方向性）

- **线值得继续**：fit 能在表面零重叠下抓到真同构——"比喻查询能发现普通检索搜不到的东西"得到第一个直接证据。
- **但"决定性"验证未完成**：还差强 baseline（真 embedding + LLM 判断）对照。若强 baseline 下 fit 的增量消失 → 停线。
- 判定标准（GPT 定）：真同构稳定排前 + 明显优于 baseline。目前"排前"成立，"优于 baseline"待强对照。

## 五、下一步（决定性对照实验）

1. **bge-m3 embedding 对照**：问题文本 vs 12 张卡全文的向量相似度排序（环境装 bge-m3，ollama 或 API）
2. **LLM 判断对照**：DeepSeek 对每张卡问"这张卡能否落入公共浴场比喻"，收集打分排序
3. 三方法排序对比：fit vs embedding vs LLM——真同构排名
4. 若 fit 排名显著优于两者 → 比喻查询线确立；否则 → 停线，转回纯签名检索

## 六、zcode 评审：预注册缺陷与修复协议（2026-08-30）

**警告 1（致命，成立）**：fit(card,M) 的核心关系 R6/R7 是**手选的，且选的时候已知道语音克隆该排第一**——n=1 查询上的事后特征选择，fit 赢在定义里。本报告 v1 的"决定性"结论**作废**。

**修复协议（v2，预注册纪律——与"回测集零自标签对、权重预注册"同一条）**：
1. **M 冻结落盘在前，候选排序在后**：M 的核心关系必须**在看到任何候选卡排序之前**从问题文本独立导出并落盘（导出者对候选盲）
2. 顺序写死：问题 → LLM/人独立抽 M（不看候选卡）→ M 落盘 → 才选候选卡 → fit 排序
3. 或直接上小黄金集（6-10 查询）摊薄单查询事后选择风险

**警告 2（保真度≠充分性）**：审计单查"M 忠实于问题"，但 faithful 投影可能丢判别性结构（只保 R1/R2 丢 R6/R7），检索照样废。分工：**保真度归投影契约，充分性归小黄金集 Recall@10 事后验收**（见投影契约 §六）。

**警告 3（真对手是 LLM 裸判断，不是 embedding）**：bge-m3 在表面零重叠场景必输（公平，论文声明即可）；但 DeepSeek 裸问"DHCP 问题+语音克隆卡"很可能也能排对——LLM 跨域类比判断本就不弱。**价值主张必须回答：结构脚手架（M+fit+契约）比裸 LLM 判断多捞到什么？**

**v2 基线设计（差值=机器净贡献）**：
```
基线 A（裸版）：问题 + 卡原文 → LLM 直接判断排序
基线 B（脚手架版）：问题 + M + 卡 → fit 排序
净贡献 = B 相对 A 在 hard negatives 和多查询一致性上的增益
裁决场：hard negatives + 跨多查询一致性，不是 n=1 榜首
```
