# AI 开发培训期 Demo 施工图：数据字典智能问答 Agent（RAG+记忆+评测）

> 提案日期：2026-08-21 ｜ 来源：《2026-08-21 个人装备审计调研》合成判断 + 用户拍板
> 定位：AI 开发培训期（2026-08-16 起 16 周）唯一主任务——造出第一件"时代买得起"的成品
> 一句话：做一个"数据字典/指标口径智能问答 Agent"，用垂直数据经验 + RAG + 记忆 + 评测四件套敲门

---

## 一、为什么做它（选型逻辑）

1. 数据字典/指标口径文档是现成数据（数据治理工作天天碰），不用造数据
2. 命中市场三个高频点：**垂直数据（数仓经验）+ RAG（知识库问答）+ 记忆（多轮追问/记住用户）**
3. 面试官一听就懂，且是真实做过的需求（扛得住深挖）
4. 本地优先天然成立（企业数据不能上云）——复用永月认知层设计

## 二、技术栈（全用已有资产）

| 层 | 选型 | 说明 |
|---|---|---|
| 模型 | DeepSeek API（.env key）主用 + Ollama 本地小模型备用 | 演示"本地优先"叙事 |
| Embedding | bge-m3（已用过） | 已有经验 |
| 向量库 | ChromaDB 或 SQLite-vec | 本地优先，不上 Milvus |
| 后端 | FastAPI（AI 开发培训在学） | 手敲纪律 |
| 记忆存储 | SQLite | 手敲，可导出=差异化 |
| 界面 | Streamlit | 半小时出聊天界面 |
| 评测 | 手工评测集（30题）+ 跑分脚本 | 市场 P0 要求 |

**手敲范围**：RAG 主流程（分块→检索→组装）、记忆模块（存→提取→注入）手敲；重复部分 AI 生成。

## 三、六模块拆解

```
① 数据层：数据字典/口径文档 → 清洗 → 分块 → bge-m3 向量化 → 存 SQLite-vec
② RAG层：混合检索（BM25+向量）→ 组装上下文 → DeepSeek 生成
③ 记忆层（差异化核心）：对话历史存 SQLite → 提取用户偏好/常用口径 → 检索注入 → 支持"上次那个指标"
④ 评测层：30题评测集 → 跑分脚本 → 准确率/漏检率报告 → Bad Case 分析
⑤ 演示层：Streamlit 聊天界面 + 架构图（mermaid）
⑥ 工程层：重试/降级/Token成本统计/配置化
```

**记忆层是灵魂**：别人做 RAG 问答只做②，加③④ = "Agent记忆"+"评测闭环"两个市场高频词的落地。

## 四、4个月施工图（与AI 开发培训课程并行）

| 阶段 | 时间 | 干的事 | 验收 |
|---|---|---|---|
| 1. 骨架 | 第1-2周 | 数据准备+向量化+RAG基础问答跑通（最小闭环） | 终端能问"XX字段什么意思"并答对 |
| 2. 记忆 | 第3-4周 | 对话历史+用户画像+记忆检索注入 | 能多轮追问"上次说的那个指标" |
| 3. 评测 | 第5-6周 | 30题评测集+跑分+Bad Case | 有准确率报告（53%→93%的叙事素材） |
| 4. 工程化 | 第7-8周 | 重试/降级/Token统计+Streamlit界面 | 能现场演示，界面能看 |
| 5. 打磨 | 第9-12周 | README+架构图+面试叙事+GitHub开源 | 能讲30分钟架构 |

**每天 2 小时给 demo，AI 开发培训课内作业优先完成**（课程项目=练手，demo=作品）。

## 五、面试叙事模板

```
背景：做数据治理时，业务同事反复问字段含义/指标口径，答一次教一次
方案：RAG知识库问答 + 记忆系统（记住用户/支持多轮）+ 评测闭环（30题跑分）
结果：准确率从X%提到Y%（要有数字）；多轮追问支持；本地部署（数据不出域）
亮点：①记忆可导出（不绑架用户）②评测驱动迭代（有量化）③垂直数据（懂业务口径）
```
