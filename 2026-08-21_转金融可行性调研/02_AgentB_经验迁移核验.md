## 二、技能翻译表（逐条：现有能力→金融岗位要求→差距→补法）

### ① 数据治理（1年政务）→ 金融数据口径管理

- **现有能力**：政务数据治理、数据质量、**口径管理**——做过指标口径定义、数据标准、质量规则。
- **金融岗位要求**：金融数据治理岗的看家活就是**口径管理**（同一指标跨部门口径冲突）、数据标准（监管报送口径）、数据质量（脏数据/缺失/不一致）。上海钢联JD原文实证："有数据治理+大模型落地经验优先"。
- **差距**：政务场景→金融场景的口径语义不同（政务口径=部门管理口径；金融口径=监管报送+业务分析双轨），但**方法论完全同构**（定义→标准→质量规则→血缘）。
- **补法**：demo把"ROE统计口径是什么""营收含不含并表子公司"做成核心场景——直接演示口径管理能力迁移。
- **核验结论**：**能迁移，且是迁移度最高的一项（约90%方法论同构）**。

### ② 数仓（1年）→ 金融数据管道/数据集市

- **现有能力**：数仓分层、ETL、数据管道、政务数据入仓。
- **金融岗位要求**：金融数据管道（行情/交易/财务数据接入）、数据集市（投研数据、风控数据）、监管数据报送管道。145/159 JD原文：**"量化策略回测与数据管道"**。
- **差距**：①金融数据时效性远高于政务（T+0行情 vs T+1报表）；②高频/时序数据结构（k线、tick）没接触过；③1年经验在"数据管道"岗里是入门档。
- **补法**：demo的"财报PDF→清洗→分块→入库"管道=数据管道缩小版，面试讲"我从原始数据到可查询指标的全链路"。
- **核验结论**：**部分能（能力成立，深度不足）**——够撑起"数据管道"叙述，撑不起"3-5年数据工程师"的岗位要求。

### ③ SQL → Text2SQL基础

- **现有能力**：数仓1年，SQL是看家技能（政务库查询/口径取数）。
- **金融岗位要求**：289条中SQL 68岗中位22K（"基础标配，不涨薪但必须"）；62/268外资银行JD原文：**"基于大模型搭建文本转SQL（Text2SQL）"**——这是金融AI落地的真实需求。
- **差距**：会写SQL ≠ 会做Text2SQL。Text2SQL需要：schema理解、NL→SQL的prompt/评测、SQL生成的准确率验证。用户完全没有NL2SQL工程经验。
- **补法**：demo的"指标口径问答"本质上就是窄版Text2SQL（自然语言问指标→SQL取数），刻意把这条讲出来；再补一个"问→SQL→执行→答"的最小链路。
- **核验结论**：**部分能（SQL基础可复用，Text2SQL工程能力需在demo里现做）**——4个月可补，不是硬伤。

### ④ Python（AI 开发培训在读）→ Agent开发

- **现有能力**：Python基础、FastAPI、RAG、Agent——**尚未结业，无生产级项目**。
- **金融岗位要求**：145/159要求Python/GPT/Agent/大模型（JD正文：**"LLM Agent编排与工作流设计"**）；289条中Agent 212岗、RAG 168岗、Python 207岗——绝对主流。
- **差距**：培训班水平 vs 岗位要求的工程化Agent（工具调用、多Agent编排、生产级错误处理）。**当前最大硬缺口**——任何岗位不会为"在学Python"付20K。
- **补法**：demo即补法——6模块（数据层/RAG层/记忆层/评测层/演示层/工程层）全部手敲，结业时有一个"能跑、能演示、有评测报告"的成品。
- **核验结论**：**条件能（demo落地前=不能，落地后=能）**——时间问题不是能力问题，2027年1月投递时点恰好卡在demo完成后。

### ⑤ 投资经验 → 金融场景理解

- **现有能力**：实盘投资牧原/创新药014564/长电，懂ROE/毛利率/PE/PB/三大报表，理解指标背后的业务含义。
- **金融岗位要求**：145/159 JD原文"**帮助投资经理发现、验证和迭代投资策略**""面向专业用户的研究工具产品"——要求理解投研工作流；62/268"协同业务团队与数据团队"——要求业务沟通。
- **差距**：散户视角→机构视角（实盘≠组合管理/风控/合规/回撤管理）；量化开发（回测/因子/风险模型）零经验。
- **补法**：评测集用真实投资问题（"牧原2025毛利率多少""创新药集采影响哪些指标"），面试可扛住深挖；诚实定位"我理解零售投资者视角，机构视角在学习"。
- **核验结论**：**能加分（业务理解维度），但不能替代量化/风控硬技能**——面试的差异化武器，不是岗位能力本身。

### ⑥ KOS认知系统/记忆工程 → AI记忆系统

- **现有能力**：KOS五层知识库架构设计（自建认知系统）、知识卡片体系。
- **金融岗位要求**：289条中记忆(Memory)全量45岗，可投池12岗中**10个（83%）落在25K+**——记忆是稀缺加分项；200JD分析确认"记忆(24%)已进入JD，尚未成标配=蓝海"；145/159虽未明写记忆，但Agent编排+专业用户产品天然需要会话记忆。
- **差距**：KOS是"个人知识管理系统"，AI记忆是"Agent运行时记忆"（对话历史→用户画像→检索注入）——概念相近、实现不同；用户尚未做过Agent记忆工程。
- **补法**：demo的记忆层（存→提取用户关注标的/口径偏好→注入）手敲实现，把KOS架构思想翻译成Agent记忆——AI 开发培训同学不会的差异化。
- **核验结论**：**部分能（思想可迁移，工程需现做）**——做成后是**简历上唯一"会的人少"的亮点**（83%的25K+岗要记忆）。

### 3.3 三个特别核验

**核验A：非科班能不能过简历关？——部分能，条件=作品+数仓经验前置+内推。**
289条原文：本科174岗（60%）薪资中位29K，统计口径未将"专业"列为硬性筛选项；200JD分析"本科88%，硕士8%——AI应用岗硕士不是门槛"。**但**行业分布原文明确"金融23岗：高薪方向，**但对学历/背景要求高**"——金融岗简历关更严。结论：**泛AI应用岗（145/159类）能过简历关（通过率估5-15%），纯金融机构数据岗难**。应对：简历第一屏放demo+数仓经验（不放培训班），海投是死路（红线清单已确认），必须内推+作品敲门。

**核验B：1年数仓在金融数据岗算不算经验？——算，但只算入门档。**
289条原文：1-3年档35岗中位20K——1年正好踩在"1-3年"下限，招聘方认可为入门级经验。金融数据岗的"数仓经验"通常要求3年以上，1年够投145/159这类"1-3年"岗，**不够投"3-5年"的金融机构核心数据岗**。但用户的经验是**数据治理+口径管理**——金融数据治理岗的稀缺交叉点（政务合规严谨性与金融合规文化同构）。结论：**算经验，且"治理"比"数仓"更值钱，但只能支撑入门档岗位**。

**核验C：投资经验面试能不能加分？——能，且是最大差异化，但只在业务理解维度。**
145/159 JD原文"帮助投资经理发现、验证和迭代投资策略"——面试官大概率懂投研，用户能说出"牧原的ROE为什么重要""创新药集采怎么影响毛利率"，这是金融科班应届（没真金白银投资过）和技术转行者（不懂业务）都给不出的回答。**但**散户视角≠机构视角：面试必须诚实定位"我理解零售投资者如何使用数据，机构视角（组合/风控/合规）我在学习"——诚实+懂业务=加分；装懂机构投研=减分。结论：**能加分，加在"业务理解与评测集设计"维度，不替代量化/风控硬技能**。

## 四、面试叙事模板：把demo讲成敲门砖

### 4.1 完整叙事（背景/方案/结果/亮点）

```
【一句话定位】
"我做了一个金融数据口径智能问答Agent——用数据治理的看家活，解决金融数据最痛的'口径混乱'问题。"

【背景】（为什么做——用真实经验起底）
"我在做政务数据治理时发现，数据服务最核心的痛点不是存储，是口径管理——同一指标，不同部门口径不同，
取数永远在扯皮。金融数据的口径问题更严重：ROE有加权/摊薄口径，营收有含/不含并表口径，分析师和
风控各说各话。我想验证一件事：Agent能不能把'口径管理'这件事做成产品。"

【方案】（技术如何呼应岗位要求）
"三层架构：①数据层——公开财报/研报/监管口径文档，清洗→分块→bge-m3向量化入库（SQLite-vec，本地优先）；
②RAG层——混合检索（BM25+向量）+上下文组装+DeepSeek生成；
③记忆层——对话历史存SQLite，提取用户关注标的与口径偏好，检索注入，支持'上次那个指标'的多轮追问。
另配30题评测集（含我自己投资时真实问过的问题）+跑分脚本+Bad Case分析。"

【结果】（数字说话）
"口径问答准确率从初版X%提升到Y%（评测闭环驱动迭代）；多轮追问支持；全程本地部署——金融数据不出域，
这是合规叙事，也是金融客户最在意的点。"

【亮点】（三个差异化，对应三块经验）
"①懂口径——1年数据治理经验，这是纯技术背景的人没有的；
②懂记忆——Agent记忆系统手敲实现，KOS知识库架构思想迁移，市场83%的25K+岗要记忆技能；
③懂金融场景——我实盘投资牧原/创新药/长电，评测集就是真实问题，我能跟投资经理对话。
④懂合规——只碰公开披露数据，知道什么能碰什么不能碰。"
```

## 五、竞品对比：同池竞争者的优势与劣势

| 竞争者 | 他们的优势 | 他们的劣势 | 用户相对优势 | 用户相对劣势 |
|---|---|---|---|---|
| **金融科班应届**（金融/会计本科+券商银行实习） | 科班背景、机构实习、CPA/CFA考证中、符合"金融背景"偏好 | **不会写代码**（无Python/Agent/RAG能力）、无真实投资经历，而Agent/RAG/Python是289条JD的硬要求 | 技术栈完整（Python/RAG/Agent/记忆）、实盘投资理解、SQL扎实 | 无金融学历、无机构实习、无证书 |
| **数据工程师转行**（3-5年数仓/ETL） | SQL/数仓扎实、经验年限够（3-5年档100岗中位28K） | **不会大模型/Agent**——289条明确把数据仓库/ETL/Spark/Flink/Hadoop列入"已删除明显无用项"（市场余晖），纯数仓单卖=红海低价 | Agent/RAG/记忆=市场新热（共现135岗）、demo差异化、投资业务理解 | 年限少2-4年、工程深度不足（高并发/分布式） |
| **算法工程师转行**（NLP/推荐背景） | 深度学习/NLP/模型功底（289条：深度学习48岗38K+8K溢价） | 不懂数据工程、不懂金融业务、薪资期望高、不爱做落地脏活 | 数据治理+SQL+业务理解=落地能力强、薪资期望务实（20-25K） | 模型功底无（Transformer/微调/训练零基础） |

**竞争格局裁决：用户的对手不是"更强的技术"或"更正的科班"，而是"卡在中间真空位"。** 金融科班不懂Agent、数据工程师不懂大模型、算法工程师不懂业务——三者都缺"数据治理×AI×金融场景"的交叉。289条里这个真空位的定价就是145/159的20-25K·14薪（本科/1-3年可投）。**用户不是去拼长板，是去占没人占的交叉点。** 风险：一旦demo没做出来（Python未结业=技术短板暴露），用户会掉回"培训班学员"池，与AI 开发培训同学拼Python基础——必输。**demo是唯一护城河。**

## 六、结论与行动清单

### 逐条核验总表

| 核验项 | 结论 |
|---|---|
| 数据治理→金融口径管理 | **能**（90%方法论同构，迁移度最高） |
| 数仓→金融数据管道 | **部分能**（能力成立、深度不足，够入门档） |
| SQL→Text2SQL | **部分能**（SQL硬、Text2SQL工程需demo现做，4个月可补） |
| Python→Agent开发 | **条件能**（demo落地前=不能，落地后=能） |
| 投资经验→金融场景理解 | **能加分**（业务理解维度，不替代量化/风控硬技能） |
| KOS/记忆→AI记忆系统 | **部分能**（思想可迁移，工程需现做；做成后=唯一稀缺亮点） |
| 非科班过简历关 | **部分能**（泛AI应用岗能，纯金融机构岗难；条件=作品+内推） |
| 1年数仓算不算经验 | **算**（卡1-3年下限，只够入门档） |
| 投资经验面试加分 | **能**（最大差异化，需诚实定位散户vs机构视角） |
| 岗位145/159 | **可投**（7项满足/条件满足，缺口=量化/前端/架构，demo第7-8周补最小回测模块） |
| 岗位62/268 | **暂不能**（硕士硬门槛，2027-2029非全硕士后=最高价值目标岗） |

### 四条行动命令（优先级排序）

1. **demo的量化模块不可砍**——145/159的"量化"二字是简历关的生死线，第7-8周必须补最小回测模块（哪怕均线+夏普），否则20-25K档金融AI岗投不进去。
2. **记忆层做透、讲成差异**——83%的25K+岗要记忆，且竞争者没人做——这是全案最便宜的差异化杠杆。
3. **投递面收窄到"金融数据×AI应用"**：145/159类为主投，上海钢联/同花顺/恒生电子/神州信息为内推目标，海投泛AI岗是浪费子弹（非科班5-15%通过率）。
4. **62/268挂远期**——现在不用管它，但Text2SQL叙事（口径问答=窄版Text2SQL）现在就要在demo里做出来，为硕士到手后的30-45K岗提前占位。
